# D1: synthetic preference contract and deterministic compiler

This is an offline research library, not preference storage or application
activation. It queries no database, registers no Flask routes, invokes no engine
and changes no bookings or permissions. All input must be explicitly synthetic.
The standalone C++ optimizer, historical references and production scheduling
remain unchanged. No D2 batching or persistent process is implemented.

## Interfaces and boundaries

- `contract.py`: strict version-1 owner intent and separate test cost policy;
  frozen parsed values, explicit states and static error codes.
- `compiler.py`: `compile_preferences(snapshot, preferences, cost_policy,
  cost_context)` returns immutable `CompiledPreferences`. `to_request()` returns
  a fresh existing `cdmcs_schedule_v1` JSON-compatible dictionary for the **full**
  candidate universe. It does not execute it or certify feasibility.
- I3a's private candidate-grid helper is extracted mechanically and shared; its
  15-minute window anchoring and all old normalization/serialization guards stay
  unchanged. Existing DTOs, normalization and protocol codecs are reused.
- Only `Snapshot(origin="synthetic")` is admitted. I3b database-origin snapshots
  are rejected, even if their records were generated by a test. Their missing
  preferences are not replaced or relabeled. I3c's synthetic test declaration
  does not authorize this compiler to process real calendars.

Synthetic markers and provenance are assertions by a trusted fixture author,
not authentication, anonymization or a sandbox against malicious Python callers.
Prepared requests contain calendars and preferences; they are not public UI DTOs.
Sanitized repr/error messages withhold their contents. There is no file exporter.

## Exact preference contract

All object fields below are required; unknown fields/versions are rejected. JSON
can be decoded with `load_document(bytes)`: UTF-8, at most 4 MiB, one document,
no duplicate members or nonfinite numbers (including exponent overflow such as
`1e999`). No handwritten JSON parser is used.

This is one **fictional configured example**, not university defaults:

```json
{
  "preference_version": 1,
  "synthetic": true,
  "owner": "organizer",
  "revision": 1,
  "state": "configured",
  "timezone": "Europe/Istanbul",
  "effective": {"from": "2029-01-01", "until": "2031-12-31"},
  "preferred_weekdays": [1, 2],
  "preferred_windows": [
    {"weekday": 1, "start": "09:00", "end": "12:00"},
    {"weekday": 2, "start": "10:00", "end": "14:00"}
  ],
  "desired_gap_minutes": 15,
  "provenance": {"source": "synthetic-owner-choice", "fixture_id": "fictional-D1"}
}
```

| Field | Validation/meaning |
|---|---|
| `preference_version`, `synthetic` | Exact integer 1 and boolean true |
| `owner` | Opaque snapshot participant ID; 1-256 UTF-8 bytes; no role dispatch or authority implied |
| `revision` | Integer 1 through signed-64 maximum |
| `state` | `configured`, `missing`, `unknown`, `unsupported` |
| `timezone` | Explicit valid IANA zone; must equal snapshot zone for the existing shared-local-day cost model |
| `effective` | Inclusive ISO dates `from`/`until`, 1970-2099; must cover the full cost context, not just search dates |
| `preferred_weekdays` | Unique ISO weekdays 1-7; empty list explicitly means day indifference |
| `preferred_windows` | Up to 64 `{weekday,start,end}` windows; empty list explicitly means hour indifference |
| `desired_gap_minutes` | Integer 0-1440, or explicit string `indifferent`; zero is a desired zero gap, not missing data |
| `provenance` | Exactly `{source,fixture_id}`; nonempty bounded IDs, source starts `synthetic-` |

For nonconfigured states, `effective`, `preferred_weekdays`, `preferred_windows`
and `desired_gap_minutes` must all be explicitly null. Metadata remains required.
Compilation reports `PREFERENCE_MISSING`, `PREFERENCE_UNKNOWN` or
`PREFERENCE_UNSUPPORTED`, not neutral weights or an infeasible meeting.
An absent field is `MISSING_FIELD`; null in a configured profile is `MISSING_VALUE`.
Omitting an entire required owner also reports `PREFERENCE_MISSING`.

Windows use exact `HH:MM`, half-open intervals. End `24:00` is allowed; start
`24:00`, seconds and equal endpoints are not. Overnight windows split into the
next ISO weekday, including Sunday/Monday wrapping. Every segment must agree
with explicitly preferred weekdays, unless days are indifferent. Duplicate and
overlapping windows fail; touching windows coalesce canonically. Input ordering
does not change results. These preferences remain **soft costs**, never new
availability, mandatory minimum breaks or permission to override published hours.

## Separate synthetic numerical policy

Every coefficient is explicit. This fictional example is not calibrated policy:

```json
{
  "policy_version": 1, "synthetic": true,
  "id": "synthetic-coefficients", "revision": 1,
  "rate_model": "weekday_window_tiers_v1",
  "preferred_rate": 1, "outside_window_rate": 2, "outside_day_rate": 4,
  "gap_weight": 1, "nearby_limit": 120,
  "exception_fee": 0, "move_fixed_cost": 0,
  "move_participant_cost": 0, "delay_per_day": 0,
  "provenance": {"source": "synthetic-test-coefficients", "fixture_id": "fictional-D1"}
}
```

Rates are integer cost per UTC elapsed minute, 0-10^8, ordered
`preferred_rate <= outside_window_rate <= outside_day_rate`. Gap weight is
0-100000; nearby limit is 0-10080 minutes; each fee/delay coefficient is 0-10^7.
Floats, booleans as numbers, strings as numbers, missing values and conflicting
tiers fail. Policy version, ID, positive revision and provenance are mandatory.
No student/professor-specific weights, production defaults, independent
back-to-back penalty or movement-distance coefficient exist.

The compiler supplies all C++ parameters explicitly, including otherwise
illustrative C++ defaults. Move/exception fees are retained for protocol fidelity,
but D1 permits no relocation or additional availability, so they cannot authorize
or introduce such actions. Optional invitees are not required scoring subjects;
their unavailability remains non-blocking. No optional-invitee ranking is added.

## Exact mathematical mapping

At each UTC minute `t`, resolve its local weekday/time in the declared IANA zone:

```text
r_p(t) = outside_day_rate, if an explicit weekday preference excludes that day;
         outside_window_rate, otherwise if explicit windows exclude that time;
         preferred_rate, otherwise.
P_p(0) = 0; P_p(k+1) = P_p(k) + r_p(anchor + 60*k).
```

One tier applies, not two added penalties. Compiled bands replace the base rate
through unchanged I3a normalization. Explicit gap indifference compiles to
`preferred_break=0, gap_weight=0`; otherwise desired gap and policy gap weight
are forwarded unchanged. Missing values never take this branch.

The C++ objective stays exactly:

```text
S_p = sum(event prefix-rate costs) + sum(adjacent gap costs)
G_p(a,b) = abs(gap - preferred_break) * gap_weight
          if gap <= nearby_limit and both EVENT START dates are the same;
          zero otherwise.
b_p = S_p(proposed) - S_p(original) + applicable existing permission/move fees
total = sum(b_p) + applicable fixed move fee + civil-day delay cost
fairness = max_p(max(0,b_p))
order = (total, fairness, start, moved_ID, replacement_start)
```

It is not primary minimax fairness. Negative net cost is valid. With desired gap
15 and weight 1, gaps 0/30 both cost 15; at cutoff 120, gap 120 costs 105 but gap
121 costs zero. Cross-midnight adjacency uses original event START dates. The
native tests verify these semantics, including negative net burdens and fairness
ties. Full-score test oracles use original intent and complete calendars, not
compiler prefix/band generation or the C++ incremental neighbor implementation.

## Required neighboring calendar context

`cost_context` is a separate explicit synthetic completeness declaration:

```json
{
  "context_version": 1, "synthetic": true, "state": "complete",
  "coverage": {"start": "2030-01-07T03:00:00Z", "end": "2030-01-07T12:00:00Z"},
  "complete_for": ["organizer", "professor-A"],
  "left_boundary": "open", "right_boundary": "open",
  "commitments": [{
    "id": "earlier-meeting", "people": ["organizer"], "resources": [],
    "interval": {"start": "2030-01-07T05:45:00Z", "end": "2030-01-07T05:55:00Z"},
    "protected": true
  }],
  "provenance": {"source": "synthetic-complete-calendar", "fixture_id": "fictional-D1"}
}
```

All fields are required. State may also explicitly be `missing`, `unknown` or
`unsupported`; none is an empty calendar. `complete_for` must include every
required participant and no unknown IDs. Commitments use I3a's original
ID/interval/people/resources/protected format, but resources and unprotected
events are unsupported in D1. IDs are unique, not `NEW`. Full intervals must fit
coverage; partial events are rejected, not clipped. Original mandatory events
must match exactly; extra mandatory busy time inside search is inconsistent.

For active gap costs, an open boundary must include padding of
`nearby_limit + 1 minute` around the earliest candidate and latest candidate end.
The extra minute captures neighbors exactly at the cutoff under half-open reads,
including cutoff zero. A fixture may instead explicitly assert `calendar_start`
or `calendar_end`: there are no outside source-calendar events on that side.
An empty query is NOT proof of closure. These declarations cannot establish the
truth of an untrusted/real calendar; they are for complete fictional fixtures.

Context enlarges the cost anchor/end while keeping the exact original candidate
universe generated by I3a. No new search times are introduced. Actual protected
meeting identities, group membership and full boundaries replace I3a's unioned
busy blocks in the final C++ input. Touching events remain separate: merging
across midnight would lose their real start-day gap semantics. Overlapping
baseline meetings are explicitly unsupported by this cost model, not silently
converted to a different calendar. If gap weight is explicitly zero/indifferent,
irrelevant outside-gap context is unnecessary; in-search completeness still is.

No semester is invented and no availability is synthesized. The optimizer still
decides every candidate's feasibility from unchanged publication and busy facts.

## Timezone and numeric safety

Each supplied preference-window endpoint for relevant local dates must be
unambiguous and existent. Original windows are retained separately from merged
rate segments: touching-window merging cannot erase an invalid endpoint, and
overnight splitting does not invent a midnight endpoint. Validation includes an
overnight window beginning the prior local day. Ambiguous/nonexistent supplied
endpoints yield unsupported computation; no clock rounding or DST guessing occurs.
A window spanning a transition with unambiguous endpoints is evaluated at actual
UTC minutes: spring gaps have fewer minutes and both fall folds receive their
corresponding wall-clock rate. Mixed participant
timezones are unsupported because the existing model has one shared day array.
Historically decreasing local-date mappings remain unsupported by I3a/I1.

Preparation retains I3c-scale safety bounds: 32 participants, 2,000 context
meetings, 10,000 memberships, 2,048 input publication windows, 256 candidates,
32-day FULL context, 200,000 total prefix entries and 4 MiB compiled UTF-8 input.
Each profile has at most 1,024 compressed bands and prefix total <=10^12.
Prefixes use exact Python integers and respect the C++ increment bound 10^8.
All limits reject the whole compilation; nothing is silently truncated.

The preserved engine's conservative signed-cost bound under its full validated
v1 limits is 43,720,003,072,000,000, below INT64_MAX. D1's subset is stricter.
Tests exercise exact prefix total 10^12, one-minute overflow, exactly 200,000
entries, overflow of that count, group fanout and native costs beyond 32-bit.

## Global delay-reference contract, version 1

`CompiledPreferences.delay_reference` records the complete original candidate
universe, timezone, minimum submitted candidate's LOCAL date and explicit delay
weight. The reference is not the first feasible candidate or first returned row.
Context padding does not reset it. `to_request()` always emits the full universe.

`check_candidates(tuple_of_absolute_starts)` is a future-scope validation helper,
not a batching implementation. It rejects duplicates/foreign/empty starts. With
positive delay weight, a subset must retain the same minimum local date as the
global universe; later-day subsets yield `GLOBAL_DELAY_REFERENCE` unsupported.
With an explicitly zero delay weight, the reference is still recorded.

Native regression: fictional day-0/day-1 rate costs 3/0 and delay weight 5 give
joint costs 3/5. A deliberately narrowed direct C++ request instead gives 0 for
day 1. D1's guard detects this; it never invents a correction or changes C++.
Future D2 must review this constraint before combining scores across requests.

Output remains capped top-K: 101 feasible candidates can return 100 rows with
`truncated=true`. The compiler retains all 101 input candidates and makes no
complete feasible-set claim from that output. Empty candidate universes cannot
have a fabricated delay origin and return unsupported compilation; a nonempty
universe with zero feasible candidates is a valid C++ evaluation.

## Verification and usage

The library accepts an existing parsed synthetic I3a Snapshot:

```python
from research.cdmcs.i3a.snapshot import parse_snapshot
from research.cdmcs.i3d.d1.compiler import compile_preferences

compiled = compile_preferences(parse_snapshot(snapshot_json), owner_preferences,
                               explicit_synthetic_policy, complete_synthetic_context)
request = compiled.to_request()  # No process launch or database access.
```

Use pinned repository dependencies and explicitly configured native binaries:

```text
python -B -m unittest discover -s research/cdmcs/i3d/d1/tests -v
python -B -m unittest discover -s research/cdmcs/i3a/tests -v
python -B -m unittest discover -s research/cdmcs/i3b/tests -v
python -B -m unittest discover -s research/cdmcs/i3c/tests -v
```

Native tests require `CDMCS_I3A_BINARY`, its `CDMCS_I3A_SHA256` and
`CDMCS_I3A_PRODUCTION` (manifest-validated); PostgreSQL regressions require an
owned synthetic `TEST_DATABASE_URL`. Use `PYTHONDONTWRITEBYTECODE=1` and
`PYTHONTZPATH=''` for pinned tzdata. Missing prerequisites skip tests and are NOT
verification. Tests invoke C++ only explicitly through the existing bounded
I3c transport; no new executor or application hook is installed.

### D1.5 correctness review and CI

Four reproducible contract defects were corrected without changing either C++
engine or the objective:

- Touching Berlin Sunday windows `01:00-02:15` and `02:15-04:00` previously hid
  their shared invalid endpoint after merging. Both the spring gap and fall fold
  are now rejected before rate compilation.
- The valid Sao Paulo overnight window `2018-11-03 23:00` through
  `2018-11-04 03:00` previously failed on an artificial midnight split boundary.
  Only actual endpoints are now checked. Across the synthetic `01:00Z-04:00Z`
  coverage, 60 nonpreferred minutes at rate 2 plus 120 preferred minutes at rate 1
  give prefix cost 240; independent full-calendar/native scoring agrees.
- JSON exponent overflow could decode to infinity despite nonfinite-literal
  rejection. A bounded-document traversal now rejects nonfinite floats at any
  nesting level. Numeric policies already rejected floats; no compiled-score
  bypass was found.
- A valid overnight preference near the 1970/2099 limits could fail because its
  supplied endpoint lay outside the scheduling epoch. Wall-time uniqueness is
  now checked without that unrelated range guard. Actual snapshot/context instants
  retain their existing bounds. UTC boundary fixtures independently yield prefix
  totals 240 and 180, respectively.

The existing isolated PostgreSQL/Release CI job now also runs D1 against its
SHA-pinned Release CDMCS and manifest-validated production binary. Each contract,
compiler and native test group is required (at least 26/40/18 tests respectively),
and any skip fails the gate. It includes the independent 20-case full-score oracle,
numerical/cutoff/fairness/delay witnesses, actual I3b-origin rejection, and silent,
sanitized failure checks. The Python gate is bounded to 300 seconds, the step to
six minutes, and the existing job container to 3 GiB/two CPUs/256 processes.

D1 changes also trigger the existing research Release, ASan/UBSan and I3a offline
jobs. I3b/identity, I3c, and full application C++/PostgreSQL regressions remain
enabled. D1 native tests use **Release**, not an ASan binary under the 256 MiB

## Remaining decisions

Real preference storage, ownership/delegation, institution calibration and common
cost units, real-calendar context/neighbor access, retention, distributed limits,
and activation still require separate approval. So do broader organizer workflows,
positive additional availability, movement consent or new objective versions.
Original SS1 optional-attendance/preferred-start ordering is not replaced by D1.
The compiler cannot infer real preferences, prove a fixture author's completeness
assertions, or make a capped recommendation list a complete feasibility result.
