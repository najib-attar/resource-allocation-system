## Read API architecture and integration boundaries

`web/professor_routes.py` validates HTTP pagination, returns private JSON and converts errors without SQL details. `web/professor_service.py` validates the active Instructor, owns the query/filter/outcome contract and uses the existing database provider. `web/app.py` registers the blueprint and excludes it from the legacy global result adapter; `web/security.py` adds only the explicit `professor.*` Instructor namespace. Existing authentication/session/CSRF code and existing endpoint permissions are unchanged.

No snapshot/result file store, new table, dependency, C++ algorithm/protocol, approval rule, notification source or presentation framework was added. No existing service was copied or reimplemented. The new regression module and reproducible browser runner supplement all existing tests; none were deleted or consolidated. There was no proven obsolete shared code to remove in this backend increment.

This matrix traces supported backend behavior; it does not claim that blocked intake, academic notifications, a new professor Home, or a completed professor frontend exists. Browser controls are inventoried in [browser/controls.json](browser/controls.json); raw state transitions and independent checks are in [browser/post-states.json](browser/post-states.json) and [browser/persistence-verification.json](browser/persistence-verification.json).
