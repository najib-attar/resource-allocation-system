## Component and integration overview

`professor_routes.py` supplies private JSON/Jinja endpoints with bounded input/error handling. `ProfessorService` is the single owner-scoped directory/intake/revision/read contract. Four forms share `_academic_request_fields.html` and existing panels/form grids. `eligibility_routes.py` and `EligibilityService` implement only administrator review. Existing base navigation adds real destinations by role. No new JavaScript, CSS framework or scheduling service is needed for these forms.

`RequestEligibility` separates administrative review from RequestDecision. The repository shares existing save validation/insertion, filters engine inputs and checks immutable run proofs before original publication logic. Migration triggers provide invalidation, immutable audit and published read-only protection outside HTTP. Existing authentication, appointment/room/equipment services, C++ sources and JSON contracts remain unchanged.

Every new visible link/form/control above is functional or explicitly unavailable for the stated reason. Browser [current gate results](eligibility-browser/browser-results.json), [before/after states](eligibility-browser/post-states.json) and [independent persistence checks](eligibility-browser/persistence-verification.json) cover actual POSTs. Current UC01–05 [control inventory](browser/controls.json) and browser evidence were rerun against this increment; results are identified in [acceptance](acceptance-report.md). No valid test or shared legacy feature was removed.
